## 实战发现并修复的问题

最初的文案请求 HTTP 成功但正文为空。随后增加空正文及截断响应校验，并按 MiMo 官方接口给文本生产步骤显式指定非思考模式，防止把空结果当作成功保存。修复后新建项目的整条实战链路通过。参考：[MiMo 官方思考模式说明](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/other/deep-thinking)。

## 当前边界

- 这是开发版：仍使用本地 Python 后端、Vite 前端和浏览器，未引入桌面打包壳。
- macOS 入口未修改；本机无法进行真实 macOS 运行验收。
- 成片采用镜头硬切；素材不足时定格末帧；不承诺实现分镜文本中的所有转场、特效或背景音乐建议。
- 原视频已经烧录的字幕或水印不会被删除；新增旁白字幕与源字幕可能同时出现。
- 成片保存在项目目录内，以保证预览和迁移；其他位置通过“下载视频”另存，已有输出不会被默认覆盖。
- 网络请求进行中时取消需要等待当前请求返回或超时；取消的结果不会写入项目。渲染支持终止正在运行的媒体进程。
- 浏览器单次上传上限 512 MB，应分批导入较大的素材集合。
- 失联的外部媒体不会按同名文件猜测替代，需重新导入。虚拟环境及 node_modules 必须按目标设备重新验证或安装，不能直接跨系统复用。
