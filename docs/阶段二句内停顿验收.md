# 阶段二句内停顿验收

日期：2026-10-24。结论：配音里过长的句内停顿会被标出来（时长和前后文字），一键可以压到上限值。压短不动语音，原配音保留，可以撤销。验收中还发现并修复了外接盘（exFAT）上导出成片和封面失败的问题。本轮 AI API 调用为 0。

## 本轮范围

- 每次对齐时（配音生成后自动对齐，或点"按配音对齐字幕"），都用 FFmpeg 静音检测（−40 dB，至少 0.12 秒）找出配音中间的停顿：
  - 首尾静音不算；
  - 结果和字幕时间一起保存在配音片段上（`subtitle_alignment.pauses`）；
  - 对齐成功时附上停顿前后的文字。
- 配音页：
  - "句内停顿上限（秒）"默认 0.5，可设 0.1–3 秒，记住上次压短用的值；
  - 超过上限的停顿在页首汇总（"N 处句内停顿超过 X 秒"），并在各段配音下用警示色标出时长和位置（停顿前｜停顿后的文字）；
  - "压短超长停顿"把超过上限的停顿压到上限值，两侧各留一半；
  - 压短完成后显示压短了几段、共缩短多少秒。字幕没有跟着更新的镜头会单独提示。
- 压短后会自动重新对齐这些镜头，存储时长、实测分句、停顿列表都按新配音更新，默认字幕也跟着更新。整个操作记一条编辑历史"压短句内停顿"，可以撤销和重做。

## 边界与保护

- **原配音文件**：
  - 原配音不改动。压短结果另存为同目录下的 `原名_停顿0.5s.wav`，用 WAV 是为了避免再做一次有损编码。已有同名文件时加序号，不覆盖。
  - 片段会记下原文件（`original_audio_path`），以后换个上限再压短，新文件仍按原名命名。
  - 撤销只是切回原文件，新文件留在磁盘上，重做时直接使用。
- **只剪静音内部**：
  - 保留下来的部分逐采样不变（实测见下文）。
  - 判断是否"超长"时，前端和后端都留 10 毫秒容差，吸收静音检测的抖动，所以压短后的停顿不会再被标出。没有超长停顿时按钮不可用。
- **不覆盖的字幕**：
  - 手动改过文字或手动定过时间的字幕不会被覆盖，压短后的提示会让你去编辑器检查。
  - 旧的压短结果只在配音还是那次结果时显示；撤销、重新生成或调严上限之后不再显示。
- **参数和依赖**：
  - 上限不在 0.1–3 秒之间时拒绝执行。
  - 压短需要 FFmpeg。对齐环境不可用时，停顿照样能检测和压短，只是没有前后文字，字幕回退为估算。

## 验收中发现并修复（影响外接盘上的工程）

- **导出和封面失败**：导出成片和生成封面的最后一步用硬链接发布文件，而 exFAT 不支持硬链接。工程目录迁到外接盘以后，导出和封面都会失败，报"Rendering failed"。
  - 现在硬链接不可用时，先用排他方式创建目标文件名再把文件移进去，仍然不会覆盖已有文件。
  - 已在外接盘上实测导出两次、生成封面一次，都成功。
- **隐藏文件被当成素材**：按文件夹导入素材、扫描素材目录时，会把 macOS 在外接盘上生成的 `._文件名` 附属文件和隐藏文件夹也当成素材；其中的"图片"会让整个打标任务失败。现在跳过所有隐藏文件和隐藏文件夹。

## 实战证据

**真实 MiMo 配音加长停顿**：取一个本机工程的副本（10 个镜头、10 段 MiMo 配音）。在其中 4 段第一个逗号处原有的自然停顿（0.12–0.14 秒）中间插入静音，再重新编码成 MP3。原工程没有改动。

| 镜头 | 自然停顿 | 插入 | 应有停顿 | 检测到 | 标出（上限 0.5 秒） |
| --- | --- | --- | --- | --- | --- |
| 第 3 段 | 0.12 | 0.80 | 0.92 | 1.05 | 是 |
| 第 6 段 | 0.13 | 1.30 | 1.43 | 1.45 | 是 |
| 第 7 段 | 0.12 | 0.25 | 0.37 | 0.37 | 否（对照） |
| 第 10 段 | 0.14 | 0.60 | 0.74 | 0.85 | 是 |

- 有两段检测值比基准长约 0.1 秒。基准是按能量另算的；−40 dB 的静音判定会把前一个字的弱尾音也算进停顿。压短只在检测到的静音里面剪，不影响语音。
- 其余 6 段的自然停顿（0.13–0.19 秒）都没有被标出。4 处停顿的前后文字都正确，落在逗号两侧。
- 对齐 10 段（含加载模型）用时 5.0 秒。

**一键压短**（上限 0.5 秒），用时 4.9 秒，包括重新对齐 3 段：

- 只改了被标出的 3 段，其余 7 段不变。新文件在原目录里，原 MP3 的哈希没有变化。
- 3 段分别缩短 0.549、0.945、0.349 秒，共 1.84 秒，与界面显示一致。存储时长与文件实际长度的误差为 0。
- 压短后重新检测，这 3 处停顿都正好是 0.50 秒；再点一次压短，没有可压的停顿。
- 语音完整性：把原配音和新配音都解码比对，停顿前后保留的部分逐采样完全相同（最大差值为 0）。被剪掉的部分最大电平 −90 dBFS，是纯静音。

**字幕**：停顿后那一句的字幕开始时间，与语音实际恢复时间的偏差（毫秒）：

| | 中位 | 最大 |
| --- | --- | --- |
| 实测对齐（长停顿配音，4 处） | 75 | 90 |
| 按字数估算（同一批配音） | 425 | 550 |
| 压短后重新对齐（3 处） | 79 | 119 |

长停顿会让按字数估算的分句明显偏离，实测对齐基本不受影响。

**成片**（在外接盘上导出 540×960）：

- 压短前成片 26.8 秒，音轨里有 3 段超过 0.55 秒的静音（1.05、1.49、0.85 秒）。
- 压短后成片 25.0 秒，没有超过 0.55 秒的静音。
- 成片短了 1.80 秒，配音共短了 1.84 秒，差值来自每个镜头的时长按整帧取整。

**撤销与重做**：编辑历史依次为"初始版本 → 按配音对齐字幕 → 压短句内停顿"。撤销后，10 段配音的文件、时长、对齐结果和字幕都与压短前完全一致；重做后都与压短后完全一致。

**界面**：在开发版 App 里打开上述副本（后端单独指向验收目录，不影响正式工程列表）。

- 配音页显示"3 处句内停顿超过 0.5 秒"，各段配音下面用警示色标出停顿时长和前后文字。
- 点"压短超长停顿"后显示"已压短 3 段配音，共缩短 1.84 秒。"。标记消失，按钮变为不可用，播放器换成了新文件。
- 在分镜页"已保存版本"里撤销后回到配音页，标记重新出现，旧摘要不再显示。
- 界面验收中修了两处：一是撤销后仍显示旧的压短摘要；二是配音卡片里的标记被卡片的文字颜色盖住，不够醒目。
- 退出 App 后没有残留进程。

## 尚未完成

- 用户对压短后节奏的确认：0.5 秒是否合适，可能要按片子类型调整。
- 真实 MiMo 配音本身的句内停顿只有 0.12–0.19 秒，本轮的长停顿是人为插入的，还没有真实出现长停顿的样本。
- 压短直接在静音里剪接，没有做淡入淡出。本轮的静音是数字静音，没有可听的接缝；底噪较大的配音剪接处是否有轻微杂音，待真实样本确认。
- 撤销后留下的新文件不会自动清理。同一上限反复"压短→撤销→压短"会多出带序号的文件，每个约 100–200 KB。
- Windows 上没有实测；exFAT 的修复也只在 macOS 上实测过。
